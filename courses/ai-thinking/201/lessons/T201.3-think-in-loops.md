# T201.3 — Think in Loops, Not One-Shot Answers

**Duration:** 2–3 minutes  
**Audience assumption:** The learner has decomposed a task into AI and human roles  
**Key concept:** Iterate while observable evidence of progress improves; stop when the loop repeats without learning.  
**Learner outcome:** Define a feedback loop, progress check, and stop condition.

## A-roll script

Welcome to the Analytics AI Enablement education series. Today in AI Thinking, we focus on thinking in loops.

One-shot expectations create two bad outcomes: an imperfect first answer is rejected too early, or a polished first answer is trusted too quickly.

Use a loop: **draft, inspect, steer, verify**. The first output makes the task visible. Inspection compares it with the goal and source. Steering changes one important condition. Verification tests whether the revision actually improved the result.

Suppose a summary is accurate but too broad. Do not restart with a giant prompt. Say: “Keep the same evidence, but focus on the three changes that affect the decision.” Then compare the new version with the original acceptance criteria.

Iteration is productive only when it creates information or reduces a known gap. Track a small progress signal: number of failed checks, unresolved assumptions, missing sources, or rubric score. Change one important variable at a time so you can tell what helped.

Watch for wandering. Repeatedly asking for another version without a clearer goal is not a feedback loop. Neither is retrying after the same failed check with no new context or strategy. Set a stop condition: after two attempts without improvement, pause, diagnose the failure, and either add evidence, change the approach, escalate to a domain owner, or stop.

The boundary is that more turns can compound a wrong assumption. Ask which assumptions are carrying forward and correct them explicitly. Begin fresh when the next task is unrelated or the conversation is tangled.

For one real task, write the draft, inspect, steer, and verify steps. Add one progress measure and the condition that ends or escalates the loop.

## Immediate exercise and feedback loop

Run one focused refinement. Compare the before-and-after result against the same acceptance check and record whether the gap narrowed.

## Boundary

Iteration can carry forward false assumptions; repeated activity without a stronger check is not progress.
