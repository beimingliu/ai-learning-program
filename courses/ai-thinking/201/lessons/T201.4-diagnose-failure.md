# T201.4 — Diagnose Failure Before Escalating

**Duration:** 2–3 minutes  
**Audience assumption:** The learner uses iterative loops with progress checks  
**Key concept:** A poor result can come from several system components; inspect them in a stable order before changing the model.  
**Learner outcome:** Diagnose one poor result and choose the smallest useful intervention.

## A-roll script

Welcome to the Analytics AI Enablement education series. Today in AI Thinking, we focus on diagnosing failure before escalating.

When an AI result is poor, “the model failed” is a tempting diagnosis. It is often only a description of disappointment.

Use this sequence.

First, check the **goal**. Is the desired outcome observable, or did the request name only an activity such as “analyze this”?

Second, check **context**. Did the agent inspect the authoritative source, business definition, examples, and constraints? Is irrelevant material crowding the task?

Third, check **tools and access**. Does the needed capability exist, does it point to the correct system, and are the credentials scoped correctly?

Fourth, check **permissions**. Is the agent unable to act because approval or policy blocks the step? Do not solve a valid boundary by widening access casually.

Fifth, check the **model and effort**. Is the reasoning task genuinely too complex for the approved default after the earlier conditions are fixed?

Finally, check the **definition of done**. If success is vague, the loop cannot reliably verify progress or know when to stop.

Imagine a report that omits a region. Upgrading the model will not help if the relevant file was never loaded or the date filter excluded it. The smallest intervention is to correct the source or filter, rerun the coverage check, and observe the result.

The boundary is that causes can interact. Fix one likely cause and rerun the same check; if nothing changes, record the evidence and move to the next hypothesis rather than changing everything at once.

Choose one disappointing result. Walk the sequence and write: observed failure, likely layer, smallest change, and the check that would confirm or reject your diagnosis.

## Immediate exercise and feedback loop

Run the smallest diagnostic change and repeat the same check. If the result does not improve, cross out that hypothesis and test the next one.

## Boundary

Failure causes can interact; change one condition at a time when practical so the evidence remains interpretable.
