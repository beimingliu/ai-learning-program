# B201.3 — Choose a Model and Effort Level in Practice

**Duration:** 2–3 minutes  
**Audience assumption:** The learner can define a checkable task and approved tool path  
**Key concept:** Model and effort changes are operating decisions that should improve a named constraint.  
**Learner outcome:** Compare two approved settings on one representative task.

## A-roll script

Welcome to the Analytics AI Enablement education series. Today in Building with AI, we focus on choosing a model and effort level.

Model choice becomes useful when it changes a measurable outcome—not when it becomes a brand argument.

Start with `[APPROVED MODEL OPTIONS]` and the organization default. Choose one small representative task from your workflow: extract five fields, explain a query, classify feedback, or draft a summary whose evidence you can check. Record the expected format and two or three checks before running it.

Run the task on the approved default. Record correctness against your checks, any important omission, elapsed time, and the available cost or usage signal. If it succeeds, keep the default.

If it fails, do not switch immediately. Ask: Was the goal ambiguous? Was the source actually inspected? Was the correct tool available? Did a permission block the action? Was the success check concrete? Fix the first failing condition and retry once.

Only then compare another approved choice. A faster tier may fit a simple repetitive task. A stronger reasoning tier may fit a complex or ambiguous task. An effort control may be enough when the same model needs more deliberation. Change one variable at a time so you know what mattered.

A single run is not a model evaluation. It is a practical operating check. Important recurring workflows need repeated representative trials at the next level.

Your action is to complete a two-run comparison only if the default misses a defined need. Finish with a one-sentence rule: “Use the default for ___; change to ___ when ___, because the check showed ___.”

## Immediate exercise and feedback loop

Complete the model decision card and review the choice against evidence from the run. Reject explanations based only on preference or reputation.

## Boundary

One comparison run supports a task decision, not a general claim that one model is better.
