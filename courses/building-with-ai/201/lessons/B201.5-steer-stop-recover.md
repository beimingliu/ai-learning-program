# B201.5 — Steer, Stop, Reject, Inspect, and Recover

**Duration:** 2–3 minutes  
**Audience assumption:** The learner can choose a conservative permission mode  
**Key concept:** Control continues during the run: steer early, stop wrong action, inspect state, and recover only what is reversible.  
**Learner outcome:** Correct and recover from one harmless detour.

## A-roll script

Welcome to the Analytics AI Enablement education series. Today in Building with AI, we focus on steering, stopping, and recovering.

Confidence does not require believing the agent will never go wrong. It requires knowing the exits.

First, **steer**. If the evidence is right but the output is too long, say: “Keep the same evidence, but reduce this to five bullets and show exact values in a table.” If the result carries a bad assumption, ask which assumptions are being carried forward and correct the specific one.

Second, **stop**. In the current CLI, Escape interrupts the active response or tool call. Other approved surfaces provide a stop control. Work already completed may remain, so stopping is followed by inspection, not immediate retry.

Third, **reject**. A permission request or proposed plan is a decision point. Decline it, explain the boundary, and ask for a safer alternative.

Fourth, **inspect**. Open the output, review the diff or changed records, run `git status` where appropriate, and compare the current state with your definition of done.

Finally, **recover**. Claude Code checkpoints can restore tracked conversation or file-edit state. The current CLI exposes rewind by pressing Escape twice, and interfaces may provide a checkpoint control. Checkpoints do not unsend email, guarantee database rollback, reverse every command, or restore every external service. Use version control, copies, backups, sandboxing, and system-specific recovery for those actions.

Your action is to create a harmless detour in a copied practice file: steer once, interrupt once, inspect what changed, and open the recovery control. Learn the sequence before a real task needs it.

## Immediate exercise and feedback loop

Run the harmless detour. The exercise passes only when the learner can state what remained changed after stopping and which recovery mechanism applies.

## Boundary

Session checkpoints cover tracked file edits and conversation state, not every external side effect.
