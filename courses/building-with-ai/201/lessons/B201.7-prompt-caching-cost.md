# B201.7 — Prompt Caching and the Cost of Agentic Work

**Duration:** 4 minutes 10 seconds (computed; retime to the final narration)  
**Timing basis:** 136 words per minute, section gaps 0.8s (1.0s before Continue Learning)  
**Audience assumption:** The learner runs multi-step agent tasks and can switch models or harnesses  
**Key concept:** An agent re-reads its whole context on every call; the harness decides whether that re-reading hits the cache.  
**Learner outcome:** Pick a model and harness pairing that caches well, and check its hit rate before relying on it.

## A-roll script

(0:00–0:07) | Series Introduction

Welcome to the Analytics AI Enablement education series. Today in Building with AI, we focus on prompt caching.

(0:08–0:35) | The Agent Re-reads Everything

An agent works differently from a chat. Every time it calls a tool, it sends the whole conversation back to the model: the system prompt, the tools, every file it read, every result so far. In my own session logs, an agent reads more than a hundred tokens for every token it writes. So agentic work mostly costs re-reading the same context.

(0:36–1:15) | What the Cache Stores

Before a model writes anything, it processes your prompt and stores a key and a value for every token, at every layer. That stored state is the KV cache. If the next request starts with exactly the same tokens, the provider reuses it and processes only what is new.

Two rules follow. Only an exact prefix counts: change one token near the top, and everything after it is processed again. And the cache expires. On Claude, the default lifetime is five minutes, reset each time it is used.

(1:16–1:38) | What a Hit Is Worth

Reading from the cache costs a tenth of the normal input price on most Claude models. Writing to it costs one and a quarter times. It is faster too: Anthropic measured a one hundred thousand token prompt dropping from eleven and a half seconds to about two and a half before the first word.

(1:39–2:35) | Same Model, Different Harness

Here is what I found in ninety days of my own sessions. This is one person's usage, not a benchmark. Claude Code with Claude models reused ninety-three percent of its input. Codex with GPT models reused about ninety. Claude Code pointed at GPT or open-weight models reused nothing, across more than a thousand calls before this week.

Same GPT models, different harness. The provider decides what can be cached; the harness decides whether each request starts with the same bytes as the last.

Both harnesses went through the same LiteLLM proxy. Codex speaks OpenAI's format, so nothing is translated. Claude Code's requests are translated on the way. In my tests, the break came down to one detail: Claude Code sends a mid-conversation notice as a list the first time, and as plain text after that. Anthropic's cache still hits, so it appears to treat them as the same. After translation they are different bytes, so the cache breaks there on every call.

(2:36–2:54) | Time Is the Other Half

Even in a pairing that works, time matters. In my logs, calls made within a minute of the last one hit ninety-nine percent. After more than five minutes idle, the hit rate fell to twenty-six percent, and most of the context was written again.

(2:55–3:24) | The Calculation

Now a worked example, modeled rather than measured: one hundred calls, with context growing to about one hundred thirty thousand tokens. At my measured hit rate, input costs about sixty percent more than the ideal. With no hits and a write premium on every call, it costs about eleven times the ideal. On a short, eight-call task the gap is small in dollars, so choose the model you want.

(3:25–3:58) | Four Habits

1. Pair each model with the harness built for it: Claude models in Claude Code, GPT models in Codex.

2. After a long break, start fresh instead of resuming a large session, or use the one-hour cache if your setup offers it.

3. Avoid switching models or compacting mid-task. Both discard the cache.

4. When you try a new pairing, check the cache numbers after ten calls, before you give it a day of work.

## Immediate exercise and feedback loop

Open the usage for your last long session (`/usage` in Claude Code, or the token counts in your harness's session log) and find its cache hit share. If it is below about 80 percent, name the likely cause: idle gaps, a model switch, compaction, or a translated pairing.

## Boundary

The hit rates and idle-gap numbers come from one engineer's own session logs through one LiteLLM proxy over ninety days (June 27 to September 25, 2026), not a benchmark. The diagnosis comes from that engineer's replay tests; that Anthropic treats both message forms as the same prefix is inferred from Opus's hit rate, not tested directly. The cost figures are a model built on list prices, not a measured bill. Prices and cache lifetimes change often; check the provider's current documentation before using these numbers for a budget.
