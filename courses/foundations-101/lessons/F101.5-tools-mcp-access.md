# F101.5 — Files, Tools, and MCP

**Duration:** 3 minutes 9 seconds  
**Timing basis:** 136 words per minute, section gaps 0.8s (1.0s before Continue Learning)  
**Audience assumption:** The learner can tell loaded context from unloaded sources and write durable guidance into the right CLAUDE.md scope  
**Key concept:** Use the simplest approved route that supplies the necessary data and no unnecessary capability.  
**Learner outcome:** Choose among a local file, an existing tool, and an approved MCP connection.

## A-roll script

(0:00–0:08) | Series Introduction

Welcome to the Analytics AI Enablement education series. Today in Foundations, we focus on files, tools, and MCP.

(0:09–0:41) | Just Connect It to MCP

Someone has probably told you to “just connect it to MCP,” and you nodded without being certain what you were agreeing to.

The useful question underneath is smaller. How much of your data does this one task actually need to reach?

Because a connector is not a permission slip. Every route you open expands what the agent can reach. Choose the narrowest approved route that can finish the task, then start read-only.

(0:42–1:17) | The Three-Route Ladder

Use this order.

First, use a **local file** when approved data already exists in a stable export.

Second, use an **existing trusted tool** when it already performs the operation reliably.

Third, use an organization-approved **MCP connection** when repeated work needs structured, current access to an external system.

MCP stands for Model Context Protocol. It is a standard way for a server to expose selected tools or resources to an AI client. The server, credential, and policy still determine what is reachable.

(1:18–2:08) | One Task, Three Possible Routes

Suppose the weekly-customer investigation needs five support tickets.

A CSV export is enough for a one-time, point-in-time analysis. It is easy to inspect, freeze, and share with the source artifact.

An existing ticket command may fit a familiar query when the team already trusts its output.

An approved MCP connection may fit repeated work that needs current ticket fields and consistent structured retrieval.

Do not choose MCP because it is newer. Choose it when the task needs live, repeatable, structured access and the organization has approved that route.

For every route, name the minimum records, fields, date range, and action. “Read five tickets from last week” is narrower than “access the ticket system.”

(2:09–2:40) | Keep Five Questions Separate

Do not collapse every concern into the word “safety.”

**Access** asks what the agent can reach.

**Permission** asks what it can do without another approval.

**Correctness** asks whether the result is right.

**Recovery** asks whether the action can be reversed.

**Governance** asks whether policy, audit, ownership, and retention requirements are satisfied.

A connector mainly addresses access. It does not prove correctness, supply approval, create a recovery path, or satisfy governance by itself.

(2:41–2:58) | Make the Route Decision

Choose one real task. Classify its route as local file, existing tool, or approved MCP. State the minimum data and capability required.

If you cannot name an approved route, stop and ask the system owner. Do not improvise access.
