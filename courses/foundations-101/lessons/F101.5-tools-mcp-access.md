**Key concept:** MCP is the standard plug that lets Claude reach other systems through named tools. ## A-roll script

(0:00–0:07) | Series Introduction

Welcome to the Analytics AI Enablement education series. Today in Foundations, we focus on files, tools, and MCP.

(0:08–1:10) | What MCP Is

In the last lesson, you wrote down where the source of truth lives. This lesson is about how Claude reaches it.

Without a connection, Claude works from the conversation, the files on your machine, and what it can run or look up on the web. It can't see your email, your Jira tickets, or last week's Slack thread. If the data is already in a file on your machine, you don't need a connection. For everything else, Claude uses MCP.

MCP stands for Model Context Protocol. It's an open standard for connecting AI tools to other systems. The usual comparison is a USB-C port: one standard plug, instead of a different cable for every device. Each connection gives Claude a set of named tools, like search messages or read ticket. Claude picks a tool, calls it, and reads what comes back.

(1:11–1:52) | The Gateway You Already Have

At Aledade, you don't set up each connection yourself. The standard Claude Code setup includes the MCP Gateway, one approved connection to many company services.

To sign in, type slash M C P, pick the Gateway, and choose Authenticate. Okta opens in your browser. The first time Claude uses each service, you approve it in the browser, then choose Retry in Claude Code. If a tool stops working later, choose Re-authenticate in the same menu. For most services, the Gateway connects as you, so Claude sees only what your own account can see.

(1:53–2:46) | Six Services Worth Learning

The Gateway reaches many services. Six are worth learning first. Glean for search, three Google services, Slack for conversations, and Jira for tracking work.

Glean searches many company sources at once, like Confluence, Google Drive, and Jira. Start there when you don't know where something lives. Slack lets Claude search channels and catch up on threads. Gmail lets it find and read email. Google Drive holds your docs, sheets, and slides. Calendar shows your schedule, so Claude can help you prepare for a meeting. And Jira lets it read tickets and search by status or assignee.

Most of the context behind your analytics work lives in these six, and they're the sources you'll connect when you build agentic workflows later.

(2:47–3:38) | Let Claude Do the Research

Glean is where this saves the most time. Say someone asks how your team defines a metric. You'd normally search Confluence, then Drive, then Slack. Instead, ask Claude to search Glean, read the most relevant documents, and summarize the definition with a link to each source. Claude may run several searches, adjusting the terms as it goes, which is the slow part you'd otherwise do by hand.

Two things worth knowing about Glean. It only finds what you can already open, so an empty result can mean you don't have access, not that nothing exists. And for Slack, ask Claude to search Slack directly, because Glean's copy of Slack is delayed and can miss messages.

(3:38–4:25) | Writes Go Out Under Your Name

Some Gateway tools write. They can post to Slack, send an email, add a calendar event, or edit a Jira ticket, all under your name. So ask for a draft, review it, and send it yourself.

Asking for a draft doesn't switch the write tools off. By default, Claude Code asks before it uses a Gateway tool you haven't allowed yet. Read that prompt, and say no to anything you didn't ask for. It also helps to say draft only, don't send, in plain words.

And keep patient information out of web searches. For anything else Claude sends out, check that it belongs where it's going.

(4:26–4:42) | Make One Research Request

Pick one question you'd normally dig through docs to answer. Ask Claude to search Glean, summarize what it finds, link each source, and change nothing. Then open one source link, and check the answer against it.

(4:43–4:53) | Continue Learning

Explore other videos in this series, and leave a comment in the Analytics AI knowledge sharing channel so we can improve the course.

This lesson departs from the series' card-and-terminal pattern. Real Gateway output would show real names, messages, and tickets, so **no screenshots of live tools**. - **Approval prompt mock:** a stylized Claude Code prompt ("Allow `slack · chat_postMessage`?  Yes / No") drawn in the terminal palette, not a screenshot.

## Boundary

The Gateway reaches systems with your own access for most services. It does not make an answer correct, approve a write, give you an undo for a sent message, or decide whether data belongs in a request. In Manual mode, the default, the approval prompt is the day-one control on writes; an allow rule removes it for that tool, unless the tool or an organization setting always requires approval. Permission modes (auto mode is in B201.4), enforcement, and recovery paths belong to Building with AI 201.
