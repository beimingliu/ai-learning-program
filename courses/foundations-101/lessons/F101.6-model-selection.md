# F101.6 — Model Selection and Effort

**Duration:** 4 minutes 36 seconds (rendered cut, 2026-09-26)  
**Release:** early October 2026. Model names and defaults change with each release; the two-question diagnosis and the shape-of-work lanes are the durable part.  
**Timing basis:** 136 words per minute, section gaps 0.8s (1.0s before Continue Learning). Set the exact duration from the regenerated A-roll.  
**Audience assumption:** The learner can write a task brief, load the right context, and reach a source through a tool or MCP  
**Key concept:** Fix the task before you change a setting. Then ask one question: did Claude not know enough (change the model) or not try hard enough (raise the effort)? Choose by the shape of the work, not the brand.  
**Learner outcome:** Pick a starting model and effort level for one recurring task, and name the evidence that would justify a change.

## A-roll script

(0:00–0:08) | Series Introduction

Welcome to the Analytics AI Enablement education series. Today in Foundations, we focus on model selection and effort.

(0:09–0:46) | More Models Than Ever

Open the model picker, and you'll see a few names. Aledade's model gateway offers many more: Claude models from Anthropic, GPT models from OpenAI, and open-weight models like GLM, Kimi, and DeepSeek. Open-weight means anyone can download and run the model. On our gateway, they also cost much less to use. New models arrive every few weeks. When a result disappoints, the instinct is to pick the biggest name and hope. That's usually the wrong first move.

(0:47–1:20) | Fix the Task First

Before you change the model, check the task. Is the goal specific? Did Claude read the right source? Does it have the tool it needs? Is there a check that shows when it's done? A bigger model can't open a file it was never given, or fix a metric definition that was wrong to begin with. If your brief says count every visit when you meant completed visits, fix the brief, not the model. When Claude gets it wrong, look at the context before you touch a setting.

(1:21–2:18) | Two Settings, Two Questions

Once the task is clear, you have two settings. The model decides how capable the worker is. Effort decides how hard it works: how much it reasons, how many files it reads, and how far it goes before it checks back with you. So ask one question. Did Claude not know enough, or did it not try hard enough? Say Claude gets last month's visit count wrong. If it read the right table, ran your check, and still got it wrong, it didn't know enough: pick a stronger model. If it skipped the check, it didn't try hard enough: raise the effort. Anthropic's own tests show the same split: more effort caught more missed edge cases, but it didn't fix a wrong approach. In Claude Code, type slash effort. More effort makes those steps likely, not certain, so you still check.

(2:19–2:57) | Choose by the Shape of the Work

Choose by the shape of the work, not the brand or the version number. For routine work you can describe exactly, like explaining one SQL file, use a fast, low-cost model: Haiku, GPT Luna, or GLM Flash. Everyday models, like GPT Sol, fit most analysis, writing, and coding. The strongest models, like Opus or GPT Astra, fit ambiguous problems, like a dashboard number that won't match its source. The names will change; these three kinds of work won't.

(2:58–3:22) | Match the Model to Its Harness

A model works best in the harness built for it: Claude models in Claude Code, and GPT models in Codex. Pick the model when you start, and keep it. Switching mid-session throws away the cache, and answers can get worse. If you need a different model, start a new session. Building with AI 201 explains why.

(3:23–3:57) | Start at Medium

Start with the model your setup gives you, and set effort to medium. That's our default. Higher effort costs much more, and often adds little. Raise effort when the work has many edge cases, like a quarter-end reconciliation. Lower it for a quick draft you'll steer, like a first outline of a memo. Change one setting at a time, on the same task with the same check. Building with AI 201 shows how, and what each step costs.

(3:58–4:25) | Record the Decision

Now try it. Staff it like a team: routine work goes to an analyst, and the expert comes in only when needed. For one task you do often, finish this sentence. I'll start with this model because of this, and switch only if this check fails. For example: GPT Sol for the weekly memo, because it's everyday writing, and Opus only if the totals don't match the dashboard.

(4:26–4:36) | Continue Learning

Explore other videos in this series, and leave a comment in the Analytics AI knowledge sharing channel so we can improve the course.

## Immediate exercise and feedback loop

Pick one task you do often. Start at medium effort and keep the same model for the session. Finish the sentence: "I'll start with ___ because ___, and switch only if ___." Example: "I'll start with GPT Sol for the weekly memo, because it's everyday writing, and switch to Opus only if the totals don't match the dashboard." A reviewer should challenge the choice using the task's difficulty, value, speed, cost, or evidence, not brand preference.

## Boundary

A stronger model cannot compensate for an unclear goal, missing context, an unavailable tool, a blocked permission, or a weak check. The lanes are starting points, not claims of equal performance across providers. Benchmark cost figures (Artificial Analysis Intelligence Index) are left to Building with AI 201, where the question moves from getting the work done to getting it done on the right model and harness within a reasonable budget. Which models you can use comes from Aledade's approved setup and the company model guide, which change often. Harness pairing and cache cost belong to Building with AI 201 (B201.7); comparing settings on representative runs belongs to B201.3.
