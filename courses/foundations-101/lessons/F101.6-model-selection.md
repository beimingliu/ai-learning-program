# F101.6 — Model Selection and Effort

**Duration:** 4 minutes 22 seconds (rendered cut, 2026-09-26)  
**Release:** early October 2026. Model names and defaults change with each release; the two-question diagnosis and the shape-of-work lanes are the durable part.  
**Timing basis:** 136 words per minute, section gaps 0.8s (1.0s before Continue Learning). Set the exact duration from the regenerated A-roll.  
**Audience assumption:** The learner can write a task brief, load the right context, and reach a source through a tool or MCP  
**Key concept:** Fix the task before you change a setting. Then ask one question: did Claude not know enough (change the model) or not try hard enough (raise the effort)? Choose by the shape of the work, not the brand.  
**Learner outcome:** Pick a starting model and effort level for one recurring task, and name the evidence that would justify a change.

## A-roll script

(0:00–0:08) | Series Introduction

Welcome to the Analytics AI Enablement education series. Today in Foundations, we focus on model selection and effort.

(0:09–0:43) | More Models Than Ever

Open the model picker, and you'll see a few names. Aledade's model gateway offers many more: Claude models from Anthropic, GPT models from OpenAI, and open-weight models like GLM, Kimi, and DeepSeek. Open-weight means anyone can download and run the model. On our gateway, they also cost much less to use. New models arrive every few weeks.

When a result disappoints, the instinct is to pick the biggest name and hope. That's usually the wrong first move.

(0:44–1:14) | Fix the Task First

Before you change the model, check the task. Is the goal specific? Did Claude read the right source? Does it have the tool it needs? Is there a check that shows when it's done?

A bigger model can't open a file it was never given, or fix a metric definition that was wrong to begin with. When Claude gets it wrong, look at the context before you touch a setting.

(1:15–2:12) | Two Settings, Two Questions

Once the task is clear, you have two settings. The model decides how capable the worker is. Effort decides how hard it works: how much it reasons, how many files it reads, and how far it goes before it checks back with you.

So ask one question. Did Claude not know enough, or did it not try hard enough? If it had everything it needed, clearly tried, and was still wrong, pick a stronger model. If it skipped a file, didn't run the check, or stopped halfway, try more effort. Anthropic's own tests show the same split: more effort caught more missed edge cases, but it didn't fix a wrong approach. In Claude Code, type slash effort. More effort makes those steps likely, not certain, so you still check.

(2:13–3:12) | Choose by the Shape of the Work

Choose by the shape of the work, not the brand or the version number.

For routine work you can describe exactly, like explaining one SQL file, use a fast, low-cost model: Haiku, GPT Luna, or GLM Flash.

Everyday models, like Sonnet or GPT Sol, fit most analysis, writing, and coding.

The strongest models, like Opus or GPT Astra, fit ambiguous problems and stubborn bugs. The names will change with the next release; these three kinds of work won't.

Cheaper models are closer than you might expect. In a five-task test I ran in September, GPT 5.6 Luna scored almost as well as Opus 5, for about one cent per task instead of almost three dollars. That's one small test, not a ranking, but it's a good reason to try the cheaper model first.

(3:12–3:28) | Match the Model to Its Harness

A model works best in the harness built for it: Claude models in Claude Code, and GPT models in Codex. Building with AI 201 explains why, in Prompt Caching and the Cost of Agentic Work.

(3:29–3:59) | Start With the Default

Start with the default your setup gives you. Each model's default effort is set for most work. Lower it when you want a quick draft that you'll steer yourself. Raise it when the work has many edge cases to check. When you do change something, change one setting at a time, on the same task with the same check. Building with AI 201 shows how to run that comparison.

(4:00–4:15) | Record the Decision

Now try it. Pick one task you do often, and finish this sentence. I'll start with this model, because of this. I'll switch only if this happens, and I'll judge the switch by this check.

(4:16–4:26) | Continue Learning

Explore other videos in this series, and leave a comment in the Analytics AI knowledge sharing channel so we can improve the course.

## Immediate exercise and feedback loop

Pick one task you do often. Finish the sentence: "I'll start with ___ because ___. I'll switch only if ___, and I'll judge the switch by ___." A reviewer should challenge the choice using the task's difficulty, value, speed, cost, or evidence, not brand preference.

## Boundary

A stronger model cannot compensate for an unclear goal, missing context, an unavailable tool, a blocked permission, or a weak check. The lanes are starting points, not claims of equal performance across providers. The benchmark figure is one owner-run test of five tasks, not a general ranking. Which models you can use comes from Aledade's approved setup and the company model guide, which change often. Harness pairing and cache cost belong to Building with AI 201 (B201.7); comparing settings on representative runs belongs to B201.3.
