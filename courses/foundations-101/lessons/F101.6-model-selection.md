# F101.6 — Model Selection and Effort

**Duration:** 3 minutes 2 seconds  
**Timing basis:** 136 words per minute, section gaps 0.8s (1.0s before Continue Learning)  
**Audience assumption:** The learner can define the goal, source, access route, and success check  
**Key concept:** Start with the approved default; change model or effort only when the task supplies a reason.  
**Learner outcome:** Select a model tier and effort level using task evidence instead of brand preference.

## A-roll script

(0:00–0:08) | Series Introduction

Welcome to the Analytics AI Enablement education series. Today in Foundations, we focus on model selection and effort.

(0:09–0:45) | The Dropdown Nobody Explained

There is a dropdown of model names, and nobody has explained what to pick.

So when a result disappoints, the instinct is to reach for the biggest one and hope.

That is usually the wrong move, and it costs you time to find out. Before paying for a stronger model, fix the task. Start with your organization’s approved default, and change model or effort only when you can name the constraint you are solving and the check that will show it improved.

(0:46–1:25) | Choose by Work Shape

Use task shape, not version numbers.

A **fast, economical** option fits simple, repetitive, well-specified work with cheap checks. Explaining one SQL file is a good example.

A **balanced** option fits most everyday analysis, writing, coding, and multi-step work. The weekly-customer memo belongs here first.

A **strong-reasoning** option fits difficult architecture, ambiguous analysis, stubborn debugging, or high-value work with interacting constraints. The dashboard-mismatch investigation may justify it.

A **long-horizon** option, when approved and available, fits sustained investigation that must retain a plan, revisit evidence, and make progress over many steps.

(1:26–1:56) | Rule Out Non-Model Problems

Before upgrading, diagnose the workflow.

Is the goal specific? Is the authoritative source loaded? Is the required tool available? Do permissions allow the needed action? Is “done” observable? Is the check strong enough to compare results?

A stronger model cannot retrieve a missing file, repair a wrong metric definition, unlock a blocked tool, or invent independent evidence.

If one of those is the real constraint, fix it first.

(1:57–2:31) | Change One Variable

If the model fits but the task needs more deliberation, increase an approved effort control one step when available.

For important recurring work, compare representative runs using the same inputs, task brief, and checks. Measure accuracy, review time, latency, and cost.

Change one variable at a time. One impressive answer is not a benchmark.

Your organization may restrict models, rename options, or require a default. The approved model picker and current organization policy are the source of truth.

(2:32–2:51) | Record the Decision

Classify your task as simple, everyday, complex, or long-horizon.

Complete this sentence: “I will start with ___ because ___. I would change only if ___, and I will judge the change using ___.”

That sentence turns model selection from preference into a testable decision.

(2:52–3:02) | Continue Learning

Explore other videos in this series, and leave a comment in the Analytics AI knowledge sharing channel so we can improve the course.

## Immediate exercise and feedback loop

Complete the model-decision sentence for one task. A reviewer should challenge the choice using complexity, value, speed, cost, or evidence—not brand preference.

## Boundary

A stronger model cannot reliably compensate for an unclear task, missing context, unavailable tools, blocked permissions, or inadequate verification.
