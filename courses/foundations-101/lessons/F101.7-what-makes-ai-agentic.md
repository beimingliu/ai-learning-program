# F101.7 — The Agentic System and Subagents

**Duration:** 4 minutes 8 seconds  
**Timing basis:** 136 words per minute, section gaps 0.8s (1.0s before Continue Learning)  
**Audience assumption:** The learner has produced one verified artifact and has practiced placing information, choosing an access route, and selecting a model  
**Key concept:** A model reasons, tools act, context informs, the loop connects them, and a subagent checks the result from outside.  
**Learner outcome:** Explain one completed agentic loop using observable evidence, and say why a fresh-context subagent is an independent check.

## A-roll script

(0:00–0:08) | Series Introduction

Welcome to the Analytics AI Enablement education series. Today in Foundations, we focus on the agentic system and subagents.

(0:09–0:45) | What Just Happened in There

When an agent goes off on its own, reads six files, and hands back a number you cannot trace, the honest reaction is: what just happened in there?

You have run this system for seven lessons now. This is the one where you look inside it.

An agent is not just a model with a longer prompt. Four parts work together: **model, tools, context, and loop**. Naming them is what lets you say which part failed, instead of blaming “the AI.”

(0:46–1:31) | The Four Parts

The **model** reasons. It interprets the goal and chooses a next step.

**Tools** act. They read files, run calculations, and write artifacts. Without tools, the model can only return text.

**Context** informs the current step. It is the layer you learned to load deliberately rather than fill.

The **agentic loop** connects them. The agent gathers context, acts with a tool, observes the result, verifies progress, then repeats or stops.

The product wrapped around all four is the harness you met in F101.3. It decides what the model sees and what it is allowed to do. Building with AI 201 covers operating it.

(1:32–2:13) | Replay the Verified Result

Replay the Jaffle Shop analysis.

The task brief, two CSV files, and metric definitions were context. Tools read the files, calculated completed-order payment value, and wrote `jaffle-shop-report.html`. The loop inspected the sources, built the report, reconciled the total, and traced one order.

You were in the loop too. You approved the plan and decided whether the evidence was good enough to use.

The first pass kept the correct total but produced wrong monthly and payment-method breakdowns. One number right and two wrong is not “mostly working.” It is one part failing in one identifiable way.

(2:14–2:55) | A Second Agent, Fresh Context

Catching that mismatch has a name.

When you asked for a **subagent with fresh context**, you were not running the same agent twice. A subagent starts in its own context window. It does not see your conversation, the files already read, or the conclusions already drawn. It works, and returns a summary.

That isolation is the point. An agent cannot independently check reasoning it still remembers. Fresh context is what turns a second opinion into a second measurement.

The cost is that it starts cold, so state the sources and the question plainly.

(2:56–3:34) | Diagnose the Right Layer

These parts create agency, not guaranteed correctness. Any one of them can fail.

Take a failure you will meet: the report is missing a region. A larger model will not fix it. If the file was never loaded, that is context. If the connector points at the wrong system, that is tools. If the agent stopped before checking coverage, that is the loop. If the goal was never observable, the model was working from a bad brief.

Ask which part failed, and what evidence supports that answer.

(3:35–3:58) | Label What Happened

Open one completed agentic interaction. If your approved surface is chat-only, use this replay instead.

Label the model's decision, one tool action, the context used, one loop transition, and your own intervention. If a subagent checked the work, say what it could not see. Every label needs observable evidence behind it.

## Boundary

Agency describes a system's ability to act and iterate. It does not establish reliability, approval, or accountability. A subagent isolates context; it does not guarantee a correct second answer, and two agents can be wrong the same way if both read a flawed source. The harness is named here but not taught; permissions and loop controls belong to Building with AI 201.
